¿Se puede editar directamente en ShareLinks?

CONSULTA TÉCNICA

Sí, mediante una extensión de Chrome/Edge, pero debe tratarse como un proyecto separado porque escribir en ShareLinks modifica contenido corporativo y requiere sesión, permisos y protecciones contra pérdida de datos.

Fase 1 · Asistente seguro

La extensión detecta la macro HTML abierta, permite traer su contenido al constructor y devuelve el HTML al portapapeles. No guarda automáticamente.

Fase 2 · Inserción controlada

Un content script coloca el resultado dentro del editor de la macro. El usuario revisa y pulsa Guardar manualmente.

Fase 3 · Publicación

Solo si la organización lo autoriza: actualización mediante REST API de Confluence, con confirmación, versión esperada, respaldo y auditoría.

Recomendación

Empezar con la Fase 1 o 2. Evitar automatizar el botón final de guardado: ShareLinks puede tener cambios concurrentes, borradores compartidos y macros cuyo contenido se transforma antes de persistirse.

Arquitectura propuesta

  • manifest.json Manifest V3 con permisos limitados al dominio de ShareLinks.
  • content.js detecta el editor y obtiene/inserta únicamente la macro seleccionada.
  • studio.html reutiliza los constructores restringidos.
  • background.js coordina mensajes; no almacena credenciales.
  • Respaldo local antes de cada inserción y comparación de la versión de página.

Condiciones necesarias

  • Autorización de seguridad/IT para instalar una extensión interna.
  • Confirmar si ShareLinks expone REST API y si la cuenta puede editar contenido mediante API.
  • Probar primero en un espacio de sandbox.
  • Nunca extraer cookies, contraseñas o tokens desde el navegador.
